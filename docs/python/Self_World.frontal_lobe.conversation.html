add_live_thought_listener(self, listener) -> 'None'
Register a listener for Genesis's spontaneous thoughts.
 
The listener is called as ``listener(kind: str, content: str)``,
where ``kind`` is ``"thought"`` (a spontaneous inner-life
thought) or ``"learning"`` (something it learned autonomously).
It may arrive from the metronome or an infrastructure callback;
listeners must be thread-safe.

Clear all queued questions.
end_question_session_if_done(self) -> 'bool'
End the question session once nothing remains to answer.
 
The session's work is done when no popped question still
awaits its answer and the queue holds nothing more — focus
returns to the normal background. Called after every
conversation turn so the drain is recognized wherever the
answer arrived from.
enter_question_mode(self, topic: 'str' = '') -> 'None'
Enter a focused question-answer session (/teach-questions).
 
She asked; the user is answering. Takes the same posture
teaching mode does — the autonomous learner and inner life
pause so the exchange is the only thing she is doing, and
volition stays held while questions are out. The question's
target concept borrows the lesson-scope filter: her inline
curiosity stays on what the exchange is about (follow-up
questions that pertain still reach her; unrelated ones queue
for later), and the executive's task set names what she's
doing — the mechanics of focus, not just its name.
 
The session ends when the queue drains
(:meth:`end_question_session_if_done`), on /teach-questions
stop or clear, or when the user goes quiet for the
conversation focus window — whichever comes first.
enter_teaching_mode(self, topic: 'str' = '') -> 'None'
Put Genesis into teaching/training mode.
 
Pauses code scanning, autonomous learning, art, and unrelated
curiosity questions. Self-directed learning from the
conversation stays active so it remembers what it's taught.
 
Args:
    topic: Optional topic hint for curiosity filtering.

mark_user_activity(self) -> 'None'
Mark that the user is active (typing or interacting).
 
This updates ``_last_interaction_time`` from the CLI's input
loop, BEFORE responding. The heartbeat's waking-side signals
run in a separate thread and must see the user as active —
announcing sleepiness or renewing a wake drive mid-turn is
noise.
offer_utterance(self, text: 'str') -> 'None'
Offer a candidate utterance for the speech-volition to consider.
 
The CLI feeds live-thought text here. The Mind's volition engine
decides whether it actually feels like saying it.
 
During sleep, utterances are not queued — it shouldn't
accumulate speech while resting. The queue would drain when
it wakes, producing a burst of stale thoughts.
pop_queued_question(self) -> 'dict[str, str] | None'
Pop the next queued question.
 
Returns a dict with keys 'text', 'reason', 'target_concept',
'question_type', 'gap_detail', or None if the queue is empty.
Also sets the question as pending so the cognition engine
treats the user's next input as an answer.
respond(self, user_input: 'str', timeout: 'float' = 60.0) -> 'str'
Process one user turn and record its observed response latency.
 
Timing starts when the interaction enters the public response
boundary and ends when that boundary returns. This includes normal
cognition, errors, and bounded timeout fallbacks.

stream_kind(thought) -> 'str'
Which live stream this event belongs on.
 
Dream content gets its own kind so the live stream and the cognitive
journal can tell it apart from waking thought — it used to be labeled
"thought" and was indistinguishable, so a night of dreaming printed
`genesis~ [thought]` lines all night.
 
Extracted from `_on_spontaneous_thought` because it is a pure rule and
it was the thing being got wrong. Left inline, a caller that set the
kind correctly on `_emit` still had it silently overwritten here,
because this recomputes from the event's attributes rather than
trusting what the caller passed. That is invisible from any test that
stubs the emit side, and it shipped once already.
