Memory store pointers and emotional gating weights.

§manifest: RuntimeManifest

Runtime module manifest table.

§sleep_network: State

Sleep-wake network state: [f_lc, f_vlpo, f_r, f_scn, h, c, xc, n]. Authoritative, like the ions: the homeostatic sleep pressure and the circadian oscillator are not derivable from anything else. Placed after manifest so it lands on an 8-byte boundary with no padding inside the checksum region. See crate::state::sleep_network.

§ions: IonState

Ion electrochemistry — calcium, chloride, potassium, sodium. Sits ahead of the checksum because concentrations, gradients, and membrane potential are authoritative persistent state, not derived: losing them resets the cell’s resting state. See IonState.

§checksum: u32

CRC32 checksum of all preceding bytes (header.reserved excluded).

§inference_signals: InferenceSignals

Active inference signals — the generative self-model’s projection. Lives in the former reserved region (64 bytes). Not covered by the CRC32 checksum (derived state, recomputed every tick). See InferenceSignals.

pub fn apply_network_phase(&mut self)

Take the sleep stage from the sleep-wake network and publish it to the neurochemical phase and the zones.

The network decides sleep and its stages; the chemistry still names the waking phases. No override is applied here: the published phase is always the switch’s own state. The organism has no “declared sleep” — biology has none either; Process S tracks the physiological state, not the intention, so a cognitively asleep mind whose body could not cross sees the truth (a waking phase) and its desync check joins the body in whichever direction it actually went.

pub fn migrate_state(&mut self, from_version: u32) -> Result<(), CoreStateError>

Migrate a state from an older schema version to the current one.

This function provides the framework for upgrading state files when the schema changes. Currently, v2→v3 migration initializes the 6 new chemicals and fills the expanded coupling matrix.

§Migration strategy

When the schema version changes (e.g., v2 → v3):

  1. Read the old state from disk
  2. Create a new state at the current version
  3. Copy over all fields that haven’t changed
  4. Initialize new fields with defaults
  5. Recompute checksum
§Parameters
  • from_version: the schema version of the source state
§Returns
  • Ok(()) if migration succeeded (or was a no-op)
  • Err(CoreStateError) if migration is not supported

pub fn migrate_layout(&mut self, from_size: u32) -> Result<(), CoreStateError>

Migrate a state written under a different struct size but the same schema version.

Self::migrate_state dispatches on header.version, so it cannot help a file whose version label is already correct but whose header.state_size predates a same-version layout growth. This preserves the path the schema-v3 reserve was designed for: adding a field at the end of InferenceSignals grew only the signals tail, so no earlier field moved and the version stayed unchanged.

The one historical layout change handled here is the 3288 → 3296 growth from InferenceSignals::policy_authority. Because every InferenceSignals field kept its offset and only one was appended at the end, the migration is: zero the new tail, record the current size, and recompute the checksum. Nothing before inference_signals is touched, so the header, neurochemicals, zones, memory pointers, manifest, sleep network, and ions all survive intact in a same-version snapshot.

Zeroing is the correct value rather than merely a safe one: policy_authority is the authority cognition grants the inference engine to act on its own policy choice, and it must not come up non-zero from a file that predates the field. The signals block is derived state excluded from the CRC and recomputed each tick, so the new field is zero again on the first tick either way — this just means the file is not carrying a grant nobody made.

The caller must hold the flock and publish the write; see the call site in crate::store::mmap_state::open.

pub fn write_end_tail(&mut self)

Zero the padding, if any, between the end of inference_signals and Self::SIZE.

The CRC covers offsets 0..40 and 48..checksum, so such padding is outside every integrity check — but it is inside SIZE, and open() copies the whole struct out of the mapping with read_volatile. Leaving it stale would make a migrated file differ byte-for-byte between machines for no reason. Under the current layout the signals block ends exactly at SIZE, so this is a no-op retained for same-version tail growth.

§Panics

Debug builds only: if the signals block no longer ends at or before Self::SIZE, the tail and the struct have drifted apart and the range computed below would be meaningless.

pub fn compute_checksum(&self) -> u32

Compute the CRC32 checksum over the struct, excluding the checksum field itself and header.reserved.

The checksum covers two regions:

  1. offset 0..40 (magic through heartbeat)
  2. offset 48..checksum (instance_id through the field before the checksum)

header.reserved (offset 40..48) is excluded — it was the sequence-lock counter, which changed on every write and made the checksum unstable. The lock is gone; the exclusion is kept so the checksum stays byte-compatible with existing files. checksum and inference_signals at the end are excluded.

pub fn scrub_non_finite(&mut self) -> bool

Replace every non-finite float in persisted state with a documented default. Returns true if anything was changed.

The per-tick circuit breaker in NeurochemicalVector::sanitize_and_validate already covers each chemical’s fields, the coupling matrix, the effective levels and the vector-level scalars. What it does not reach is the memory gating weights and the manifest aggregates — and a tick-level breaker only runs once the loop is going, so between open and the first tick a CRC-valid but non-finite state file can still be published to lock-free readers over IPC. open is the last place that can catch it.

Note the CRC cannot detect this: a state file that legitimately contains NaN is byte-exact, so both verify and verify_checksum pass it.

pub unsafe fn read_consistent(&self) -> Option<GenesisCoreState>

Take a volatile snapshot of the state.

There is no sequence lock: this is a single read_volatile copy of the whole struct. If a writer is mid-publish the copy may be torn — callers that care can verify the CRC on the snapshot. The Option return is kept for call-site compatibility with the former sequence-lock protocol; it now always yields Some.

When to use this vs MmapState::read_consistent:

  • This method is for stack-allocated GenesisCoreState values (e.g. in unit tests) where there is no aliasing concern — the caller owns the value exclusively.
  • For mmap’d state (the production daemon, IPC handler, tick loop), use MmapState::read_consistent instead. That method operates on the raw mmap pointer and never creates a &GenesisCoreState reference to the mmap’d memory, eliminating the aliasing UB that would occur if a & from MmapState::state() coexisted with a &mut from MmapState::modify() on another thread.
§Safety

The caller must ensure that self is not being deallocated or remapped while this function runs, and that no &mut reference to the same memory coexists with the &self used to call this method. For mmap’d state, use MmapState::read_consistent instead.
