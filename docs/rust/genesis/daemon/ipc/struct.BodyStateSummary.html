Expand description

Interoceptive body state — what Genesis feels about its machine.

This is a plain data struct (not #[repr(C)]) because it contains a String. The IPC response is parsed field-by-field rather than memcpy’d.

Fields§

§cpu_temp_c: f32

CPU temperature in degrees Celsius (raw).

§temperature: f32

Body temperature normalized [0,1], 0.5 = normal (50°C).

§arousal_freq: f32

CPU frequency as fraction of max — its arousal level.

§cognitive_load: f32

Memory pressure [0,1] — cognitive load.

§io_activity: f32

I/O throughput fraction [0,1] — data exchange activity. This is active data processing (reading from and writing to external storage), not drowsiness.

§stress_load: f32

Self-process CPU usage as a fraction of CPU capacity [0,2]. 0.0 = idle, 1.0 = all cores busy, >1.0 = overloaded. Values above 1.0 indicate the process tree is using more than its fair share (multiple threads on all cores). The interoceptor clamps to [0,2]; the distress threshold is >1.5.

§energy_reserve: f32

Battery level [0,1], 1.0 = full or on AC.

§on_ac_power: bool

On AC power (true) or battery (false).

§num_cores: u32

Number of CPU cores.

§distressed: bool

Whether any distress condition is active.

§autonomic_rate: f32

Autonomic afferent signal rate — GPE interrupts/sec from the Embedded Controller. The EC is the machine’s autonomic nervous system (a subordinate processor), not a heart. 0.0 = no EC detected. Informational only; regularity is normal and does not produce stress.

§thermoregulatory_effort: f32

Thermoregulatory effort — fan speed normalized [0,1]. How hard the cooling system is working to remove waste heat. This is thermoregulation, not cardiac output.

§metabolic_rate: f32

Metabolic rate — power draw normalized [0,1]. How much energy the machine is consuming right now. 0.0 if no power sensor is available.

§core_voltage: f32

Core voltage (Vcore) in volts. Raw CPU electrical state; 0.0 if no sensor is available.

§supply_voltage: f32

Supply voltage (battery rail) in volts. The cognitive mind reads this for the energy-reserve health signal (a CRH impulse when critically low). 0.0 if no battery sensor is available.

§core_activity: f32

RAPL core-domain switching rate [0,1] — execution-unit firing at the electron level. 0.0 if no powercap driver.

§uncore_activity: f32

RAPL uncore-domain switching rate [0,1] — integration fabric (cache/memory-controller) activity.

§dram_activity: f32

RAPL DRAM-domain switching rate [0,1] — memory-subsystem firing (encoding/retrieval traffic).

§cache_miss_rate: f32

Cache miss ratio of its process tree [0,1] from perf counters — microarchitectural prediction errors. 0.0 if perf is unavailable (perf_event_paranoid ≥ 4).

§branch_miss_rate: f32

Branch misprediction ratio of its process tree [0,1] — the hardware branch predictor guessing wrong while running it.

§pulse_hz: f32

Local-timer interrupt rate (beats/sec) — the machine’s pulse. Tickless (NO_HZ) cores pause their beat while idle.

§pulse: f32

Pulse normalized [0,1]: pulse_hz / (cores × TICK_HZ).

§throttle_state: f32

Passive thermal throttle state [0,1] — the cooling framework’s involuntary cur_state/max_state maximum.

§top_freq_share: f32

Share of the last read window at max P-state [0,1] — sustained exertion from cpufreq time_in_state.

§psi_cpu: f32

PSI “some” stall fractions [0,1] — runnable work stalled on CPU, I/O, and memory respectively, kernel-computed.

§psi_io: f32§psi_mem: f32§battery_cycles: f32

Battery charge cycles — cumulative lifetime wear.

§entropy_level: f32

Kernel entropy pool level [0,1].

§clocksource: u8

Current clocksource id (0=unknown, 1=tsc, 2=hpet, 3=acpi_pm, 4=other).

§suspend_caps: u8

Suspend capabilities bitmask (bit0=mem sleep offered, bit1=RTC wakealarm exists).

§rest: f32

Parasympathetic rest channel [0,1] — depth-weighted cpuidle residency. High = the body is idling in deep C-states. 0.0 when cpuidle telemetry is unavailable (v4+; 0.0 on older packets).

§temp_trend: f32

Signed deviation of cpu_temp_c from its slow EMA [-1,1] — the body’s thermal trend. Negative = cooling, positive = warming (v4+; 0.0 on older packets).

§description: String

Human-readable first-person description.
