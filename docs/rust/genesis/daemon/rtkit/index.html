Module rtkit 

Source
Expand description

Minimal RealtimeKit client over the system bus — just enough D-Bus to request and hold a scheduling grant.

rtkit revokes an elevation when the bus client that requested it disappears: a one-shot dbus-send is rolled back seconds after it exits (measured on this host: the grant to a probe thread was gone within ~45 s while the identical request from a client that stayed connected held indefinitely). PulseAudio’s grants survive because it keeps a persistent connection — this module does the same, speaking the wire protocol directly so the daemon grows no dependencies: SASL EXTERNAL auth, the required Hello, one METHOD_CALL, then the socket stays open for as long as the caller keeps the returned stream.

Everything here is best-effort: an absent bus, a refused auth, or a denied grant all surface as Err and the caller continues at default scheduling — degraded jitter, never a failure.
