Expand description

The interoception sensor reader.

Reads hardware state from Linux sysfs/procfs and produces a BodyState. This is Genesis’s interoceptive sense — its ability to feel its own body.

Number of CPU cores (cached at startup).

Path to the CPU temperature sensor. k10temp is the AMD K10 family temperature sensor. Falls back to acpitz (ACPI thermal zone) if k10temp is not available.

Paths to per-core CPU frequency sensors.

Maximum CPU frequency in kHz (cached at startup).

§battery_path: Option<String>

Path to battery capacity.

§ac_path: Option<String>

Path to AC adapter status.

§prev_proc_cpu: HashMap<u32, u64>

Previous per-process CPU times (utime + stime in clock ticks) for delta computation. Keyed by PID.

§prev_proc_io: HashMap<u32, u64>

Previous per-process I/O counters (rchar + wchar in bytes) for delta computation. Keyed by PID.

§total_memory_kb: u64

Total system memory in kB (cached at startup).

§fan_path: Option<String>

Path to the fan PWM sensor (thermoregulatory effort). Discovered at startup by scanning hwmon for pwm1.

§power_paths: Vec<String>

Candidate paths to power draw sensors, in descending order of preference. Discovered at startup by scanning hwmon for power sensors (AMD fam15h_power, battery power_now, battery hwmon power1_input).

A list rather than a single path: a preferred sensor can exist yet read a dead 0 (fam15h_power does this on some AMD parts) while a lesser candidate is live. Reading only the first match would pin the power telemetry at 0.0 with a working sensor ignored.

§core_voltage_path: Option<String>

Path to the CPU core voltage sensor (Vcore/VDD). Discovered at startup by scanning hwmon for voltage sensors with a Vcore, VDD, or VID label. None on systems where the SMU controls voltage internally (e.g. acpi-cpufreq).

§supply_voltage_path: Option<String>

Path to the power supply voltage sensor (battery rail). Discovered at startup from BAT*/in0_input or battery-named hwmon devices. None on systems without a battery.

§prev_gpe_count: u64

Previous total GPE event count, used to compute the hardware notification rate.

§prev_loc_count: u64

Previous cumulative local-timer interrupt count (the LOC line’s per-core counters summed).

§prev_tis_top: u64

Previous cumulative jiffies spent at the maximum P-state and across all P-states (time_in_state totals) — the top_freq_share delta base.

§prev_tis_all: u64§cpuidle_states: Vec<Vec<CpuidleState>>

Per-core cpuidle sleep states, discovered at startup from /sys/devices/system/cpu/cpu*/cpuidle/state*/ — outer index is the core. Empty on hosts without cpuidle telemetry, which the CPUIDLE sensor bit then reports absent.

§cpuidle_max_depth: u32

Deepest cpuidle index seen across all cores — the normalization denominator for the rest weight.

§prev_cpuidle_us: Vec<Vec<u64>>

Previous cumulative per-state residency counters — the rest delta base. Same shape as cpuidle_states.

§temp_ema_c: Option<f32>

Slow EMA of cpu_temp_c (~60 s time constant) — the baseline temp_trend deviates from. None until the first real temperature read.

§clocksource_id: u8

Current clocksource id, detected at startup (the oscillator pacing its clock rarely changes at runtime).

§suspend_caps: u8

Suspend capability bitmask, detected at startup (bit0 = “mem” suspend offered, bit1 = RTC wakealarm present).

§rapl_domains: Vec<RaplDomain>

Discovered RAPL power domains (core/uncore/dram). Empty on systems without a powercap driver (e.g. AMD pre-17h, VMs).

§power_domain: Option<RaplDomain>

Whole-platform RAPL domain (psys preferred, else package) — the metabolic-rate backstop. Battery power_now is the better whole-system reading when it carries a real signal, but a full battery on AC honestly reports zero discharge while the machine burns wall power. An energy counter like rapl_domains, kept apart because it is differentiated for watts rather than for subsystem activity.

§perf_counters: HashMap<u32, PerfSet>

Per-PID perf counter sets for microarchitectural prediction errors (cache/branch miss ratios). Keyed by PID; PIDs that die are closed and dropped.

§perf_unavailable: bool

Whether perf counter access is permanently unavailable (perf_event_open failed once — e.g. perf_event_paranoid ≥ 4). Once set, we stop retrying to avoid syscall overhead and log spam every read cycle.

§subsystem_cpu: HashMap<u32, f32>

Per-PID CPU fraction from the last read (each process’s share of stress_load). Populated by read_self_cpu for per-subsystem telemetry.

§subsystem_io: HashMap<u32, f32>

Per-PID I/O fraction from the last read (each process’s share of io_activity). Populated by read_self_io.

§subsystem_perf_delta: HashMap<u32, [u64; 4]>

Per-PID perf counter deltas from the last read. Populated by read_perf; aggregated per-subsystem into miss ratios.

§last_read: Instant

When we last read the sensors.

§temp_warned: bool

Whether we’ve already warned about a missing temperature sensor. Prevents log spam when the sensor is permanently unavailable.

§sensor_mask: u32

Which optional sensors this machine actually has, as a bitmask of sensor constants. Established once at construction from the discovered paths, then republished with each body state so the cognitive layer can tell an absent sensor from a real zero.

The perf bit is the one that can change at runtime: perf_event_open is attempted lazily and can fail permanently on the first try, so Interoceptor::read updates it.

pub fn new() -> Self

Create a new interoceptor, discovering available sensors.

This probes the sysfs/procfs filesystem to find the temperature sensor, CPU frequency sensors, and battery/AC paths. If a sensor is not found, it gracefully degrades — the corresponding body state field will use a default.

pub fn new_with_data_dir(_data_dir: &Path) -> Self

Create a new interoceptor with a data directory.

Retained for API compatibility: the data directory used to locate the retina PID file, but the eye now lives inside the daemon’s own process — its cost already rides in the daemon’s share, so there is nothing extra to measure.

fn reap_dead_subsystems( &mut self, present: &[(Subsystem, u32)], ) -> Vec<(Subsystem, u32)>

Record which subsystems are alive, reporting any that just died.

genesis_subsystems already filters out processes that are no longer running, which is correct for measurement but loses the fact that they were ever there. This keeps the transition: a subsystem that was alive on the previous read and is gone now increments the death count and is reported once, so a crashed organ is a visible event rather than a silently shorter list.

A subsystem that has never been seen alive is not counted as a death — it was never running, which is a different fact.

The death count is a floor, not a census: a process that dies and is restarted entirely within one read interval looks alive on both sides, so the flap is invisible here. The PID in the telemetry record is what exposes it — a consumer that remembers the PID sees it change even when deaths does not move.

pub fn sensor_presence(&self) -> u32

Which optional sensors this machine actually has.

Derived from the discovered paths and cached probe results that were established at construction, so it reflects the hardware rather than what a default value would assume. Computed once: these are startup discoveries, and re-scanning hwmon and /sys/class/power_supply on every read would be pure overhead.

fn build_sensor_mask(probe: &SensorProbe) -> u32

Build the presence mask from the discovered sensor paths.

The /proc-backed channels (GPE, local timer, PSI) and the battery cycle count are probed here rather than assumed, because their absence is exactly what made a missing sensor indistinguishable from a reading of zero.

fn genesis_subsystems(&self) -> Vec<(Subsystem, u32)>

Collect the PIDs of Genesis’s own process tree, tagged by subsystem.

This always includes the daemon’s own PID and the cognitive mind’s PID (from GENESIS_COGNITIVE_PID). The eye’s capture thread rides inside the daemon, so there is no third process to tag. Dead/stale PIDs are silently skipped.

fn genesis_subsystems_with( &self, cognitive_pid: Option<u32>, ) -> Vec<(Subsystem, u32)>

genesis_subsystems with the cognitive PID injected rather than read from the environment. Keeping the env read at the outer edge lets tests exercise the filtering logic without mutating process-global state — std::env::set_var in a test races with parallel test threads reading the environment.

pub fn read(&mut self) -> BodyState

Read the current body state from hardware sensors.

This is the main entry point, called periodically from the daemon tick loop. It reads all available sensors and produces a normalized BodyState.

Body-state signals (temperature, battery) are read from global hardware sensors — they reflect the physical state of its body regardless of which process caused them. Activity signals (CPU load, memory, I/O) are read from Genesis’s own process tree only — other programs using the machine don’t make it stressed, overwhelmed, or drowsy.

fn publish_memory_mb(&self, mb: f32)

Read combined RSS of Genesis’s own process tree as a fraction of total system memory.

Returns 0.0 if no processes are readable. Other programs’ memory usage is not included — only its own cognitive footprint. Resident memory of Genesis’s own process tree, as both a fraction of total system memory and absolute megabytes.

The absolute figure exists because the manifest carries a per-module mem_usage_mb and an aggregate total_mem_mb, and both were structurally zero: nothing ever produced a memory number, so the manifest reported a mind using no memory at all while cognitive_load said otherwise. Splitting the reading this way keeps one traversal for both consumers. Publish this process tree’s absolute resident memory.

fn read_self_cpu(&mut self, pids: &[u32], now: Instant) -> f32

Read combined CPU usage of Genesis’s own process tree as a fraction of its CPU capacity (num_cores).

Computes the delta of utime + stime (in clock ticks) across all its processes since the last read, divided by the elapsed time in clock ticks × num_cores. Returns 0.0 on the first read (no previous baseline). Other programs’ CPU usage is not included — only its own effort.

Source

fn read_self_io(&mut self, pids: &[u32], now: Instant) -> f32

Read combined I/O throughput of Genesis’s own process tree, normalized to [0, 1].

Computes the delta of rchar + wchar (in bytes) across all its processes since the last read, converts to a rate (bytes/sec), and normalizes against a reference rate of 50 MB/s (a reasonable sustained I/O rate for a mix of cached and uncached reads/writes). Returns 0.0 on the first read. Other programs’ I/O is not included — only its own disk/network activity.

Source

fn read_rapl(&mut self, now: Instant) -> (f32, f32, f32)

Read RAPL per-domain switching activity.

Returns (core_activity, uncore_activity, dram_activity), each normalized to [0, 1] against a per-domain reference power. The energy counters are cumulative µJ; the delta per elapsed second is the domain’s average power — which, since CMOS dynamic power is proportional to switching activity, is a population-level readout of how hard that silicon’s transistors are firing.

These are body-state signals: RAPL domains measure the whole package, not per-process energy. Other programs’ switching contributes, the same way a fever counts regardless of cause. All zeros on systems without a powercap driver (this AMD Kabini has none — the fields stay 0.0 and produce no impulses, matching every other absent-sensor path here).

Source

fn read_rapl_power(&mut self, now: Instant) -> Option<f32>

Whole-platform power draw from the RAPL energy counter, normalized [0, 1] — the metabolic_rate backstop.

power_now and fam15h report instantaneous watts; RAPL is a cumulative microjoule counter, so the draw is its delta over the read window. None until the counter has a baseline to differentiate against (first read), matching read_rapl’s warmup. Normalized against the same 100 W reference as read_power_draw so the two paths read on one scale.

Source

fn read_cpuidle_rest(&mut self, elapsed_secs: f64) -> f32

Depth-weighted cpuidle residency over the read window — the rest channel.

For each core, each state’s residency delta divided by the window is that state’s share (states are mutually exclusive, so the shares sum to the core’s idle fraction). The rest score is the depth-weighted mean across cores: fully parked in the deepest C-state scores 1.0; busy-wait POLL residency and running time score 0. 0.0 when no cpuidle telemetry exists — the CPUIDLE presence bit stays clear there.

Source

fn update_temp_ema(&mut self, cpu_temp_c: f32, elapsed_secs: f64) -> f32

Fold a real temperature read into the slow baseline and return the signed deviation — the temp_trend channel.

The EMA is the ~60 s memory of where the body has been; the field reports the difference between now and that memory, ±5 °C saturating. First valid read establishes the baseline and reports 0 — a channel cannot claim a trend it has not yet observed.

Source

fn read_perf(&mut self, pids: &[u32]) -> (f32, f32)

Read microarchitectural prediction-error ratios for Genesis’s process tree.

Returns (cache_miss_rate, branch_miss_rate) — the deltas of cache-misses/cache-references and branch-misses/branch-instructions summed across its processes since the last read. Both are naturally ratios in [0, 1]: what fraction of the silicon’s predictions failed.

Counter sets are opened lazily per PID and closed when the PID dies. If the first perf_event_open fails for every event (paranoid ≥ 4, no PMU, container seccomp), the sampler disables itself permanently — retrying every read would just burn syscalls.

pub fn neuro_impulses( &self, body: &BodyState, neuro: &NeurochemicalVector, ) -> Vec<(NeurochemicalId, f32)>

Compute neurochemical impulses from the body state.

Returns a list of (chemical_id, impulse_magnitude) pairs. No magnitude here is a fixed constant: each offered rate is re-scaled at call time by the organism’s live level of the very chemical it targets — Self::self_scaled. A positive impulse fades as the level nears its ceiling (autoreceptor- style saturation); a negative impulse fades as the level nears its floor (there is no tone to withdraw). The values therefore set themselves from Genesis’s own state on every call; apply_impulse remains the hard bound.

Positive values increase the chemical, negative values decrease it. All values are in the same units as neuro_impulse in the IPC protocol.

This is the brainstem-level afferent reflex (NTS/parabrachial → autonomic loop): it runs on the body alone when the mind’s lease is expired. When the lease is held the same BodyState reaches the mind’s brainstem relay, which routes it through the proper regions and authors the response there.

Source

fn self_scaled( neuro: &NeurochemicalVector, id: NeurochemicalId, raw: f32, ) -> f32

Scale a raw reflex rate by the organism’s live level of the target chemical. Positive impulses scale by the live headroom factor 1 - level; negative impulses scale by the live tone level. The factor is finite-sanitized but not range-bound — this matches the mind-side relay’s semantics.

Source

fn read_avg_freq(&self) -> u64

Read average CPU frequency across all cores.

Prefer cpuinfo_cur_freq, which the kernel defines as a hardware-derived current frequency when the driver exposes it. Fall back to scaling_cur_freq only when the hardware-derived interface is unavailable. The latter is often the last requested P-state rather than the frequency the silicon is actually running. Never substitute an invented midpoint when no sensor can be read.
