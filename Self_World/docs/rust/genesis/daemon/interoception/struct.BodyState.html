Expand description

The body state — a snapshot of what Genesis feels about its machine.

All values are normalized to [0.0, 1.0] where possible, with 0.5 being the neutral/normal baseline. This makes them easy to feed into the neurochemical system and easy for the cognitive mind to interpret.

Fields§

§cpu_temp_c: f32

CPU temperature in degrees Celsius (raw, not normalized).

§temperature: f32

Body temperature normalized: 0.0 = freezing, 0.5 = normal (50°C), 1.0 = critical (100°C). Scales linearly.

§arousal_freq: f32

CPU frequency as a fraction of maximum. 0.0 = minimum frequency, 1.0 = maximum frequency. This is its arousal level — how fast it’s thinking right now.

§cognitive_load: f32

Self-process memory (RSS) as a fraction of total system memory. This is the combined RSS of Genesis’s own process tree (daemon + cognitive mind — the eye’s capture thread counts inside the daemon’s share). 0.0 = using no memory, 1.0 = using all system memory. Other programs’ memory usage does not contribute — only its own cognitive footprint.

§io_activity: f32

Self-process I/O throughput, normalized to [0, 1]. This is the combined I/O (rchar + wchar) of Genesis’s process tree, normalized against a reference rate. 0.0 = no I/O activity, 1.0 = heavy I/O. This is active data exchange (reading from and writing to external storage), not drowsiness. Other programs’ I/O does not contribute — only its own.

§stress_load: f32

Self-process CPU usage as a fraction of its CPU capacity. This is the combined CPU time (utime + stime) of Genesis’s process tree, divided by (elapsed × num_cores × clock_ticks). 0.0 = idle, 1.0 = using all cores, >1.0 is clamped. Other programs’ CPU usage does not contribute — only its own effort.

§energy_reserve: f32

Battery level: 0.0 = empty, 1.0 = full. If no battery, defaults to 1.0 (plenty of energy).

§on_ac_power: bool

Whether it’s on AC power (true) or battery (false). On AC = externally supplied, on battery = running on reserves.

§num_cores: u32

Number of CPU cores — its parallel processing capacity.

§distressed: bool

Whether any distress condition is currently active. True if temperature, load, or memory pressure is in a concerning range.

§autonomic_rate: f32

Hardware notification rate — GPE (General Purpose Event) interrupts per second from the Embedded Controller. This field is informational; GPE regularity is normal and does not produce stress impulses. 0.0 = no EC detected (e.g. a desktop without an EC).

§thermoregulatory_effort: f32

Thermoregulatory effort — fan speed normalized [0, 1]. The fan is the machine’s cooling system: it removes waste heat from the CPU via the heatsink. 0.0 = fan off, 1.0 = full speed. High fan + high temp = thermoregulatory strain. Fan off + high temp = cooling failure.

0.0 is ALSO the value when no fan sensor exists, so the reading alone cannot distinguish “fan stopped” from “no telemetry”. Every impulse keyed on this field is therefore additionally gated on the sensor being present — see neuro_impulses.

§metabolic_rate: f32

Energy-use telemetry — power draw normalized [0, 1]. How much energy the machine is consuming right now. Read from the first live candidate among AMD fam15h_power, battery power_now, and the battery hwmon bridge, in that preference order. Candidates are tried in turn, so a present-but-dead sensor (fam15h_power reports 0 on some AMD parts) does not mask a working one. 0.0 = every candidate unreadable or reporting zero, or the machine is genuinely idle. This is telemetry and does not drive neurochemistry.

§core_voltage: f32

CPU core voltage in volts (raw, not normalized). Read from hwmon voltage sensors (e.g. in0_input with a “Vcore” or “VDD” label). 0.0 if no core voltage sensor is available — on acpi-cpufreq systems (like this AMD Kabini), the SMU controls voltage internally per P-state and does not expose it via sysfs. On systems with coretemp, k10temp voltage extensions, or board-level Super I/O chips (nct6776, it87), this is the actual Vcore rail.

§supply_voltage: f32

Power supply voltage in volts (raw, not normalized). This is the battery rail voltage — the electrical potential of its energy reserve. A lithium-ion battery’s voltage sags as it discharges: ~12.6V full, ~10.5V critically low on a 12V battery. Read from BAT*/in0_input or equivalent hwmon. 0.0 if no battery voltage sensor is found (e.g. a desktop without a battery).

§core_activity: f32

Core-domain switching activity, normalized [0, 1]. RAPL “core” domain energy rate (ΔµJ/Δt) — how hard the execution units are firing. This is transistor switching in the compute silicon: thinking effort measured at the electron level. 0.0 if no RAPL core domain exists.

§uncore_activity: f32

Uncore-domain switching activity, normalized [0, 1]. RAPL “uncore” domain energy rate — the integration fabric (last-level cache, memory controller, interconnect). High uncore activity = heavy data integration between cores and memory. 0.0 if no RAPL uncore domain exists.

§dram_activity: f32

DRAM-domain switching activity, normalized [0, 1]. RAPL “dram” domain energy rate — memory-subsystem switching. 0.0 if no RAPL dram domain exists.

§cache_miss_rate: f32

Cache miss ratio of Genesis’s own process tree [0, 1]: cache-misses / cache-references from perf hardware counters. 0.0 if perf counters are unavailable (perf_event_paranoid ≥ 4).

§branch_miss_rate: f32

Branch miss ratio of Genesis’s own process tree [0, 1]: branch-misses / branches from perf hardware counters. Typical code runs 1–5%. 0.0 if perf counters are unavailable.

§pulse_hz: f32

Local-timer interrupt rate in interrupts per second. Each core’s Local APIC timer fires the kernel’s scheduler tick (the LOC line in /proc/interrupts); under tickless idle (NO_HZ) an idle core’s timer pauses entirely, so the rate both paces and reflects activity. Generated by timer hardware and the scheduler.

§pulse: f32

Timer-interrupt rate normalized [0, 1]: pulse_hz / (num_cores × TICK_HZ). 1.0 = every core at the nominal full tick rate. Clamped — kernels configured at a different CONFIG_HZ saturate above 1.0 before normalization.

§throttle_state: f32

Passive thermal throttle state [0, 1]. The maximum cur_state/max_state across ACPI “Processor” cooling devices: the kernel’s thermal framework lowering its clock because the silicon is hot, decided below the OS scheduler.

§top_freq_share: f32

Fraction of the last read window spent at the maximum P-state [0, 1] — sustained exertion, from cpufreq time_in_state deltas. arousal_freq is this instant’s speed; top_freq_share is how much of the recent past ran flat-out.

§psi_cpu: f32

Kernel pressure-stall metrics [0, 1] — PSI “some” avg10 divided by 100: the share of the last 10 s in which runnable work was stalled waiting on a resource. psi_cpu = tasks stalled on CPU contention, psi_io = stalled on storage, psi_mem = stalled on memory reclaim. Kernel-computed, involuntary — the body’s own statement that a resource ran short. 0.0 if pressure files are unavailable.

§psi_io: f32§psi_mem: f32§battery_cycles: f32

Battery charge-cycle count (raw) — cumulative lifetime wear on its energy reserve. 0.0 if unreported. A machine’s real senescence marker: the battery ships with a finite cycle budget and this counter is its odometer.

§entropy_level: f32

Kernel entropy pool level [0, 1] — /proc/sys/kernel/random/entropy_avail normalized by the CRNG pool capacity (256 bits). A reservoir of hardware-noise unpredictability the machine consumes for cryptography.

§clocksource: u8

Which oscillator currently paces the clock: 0 = unknown, 1 = tsc, 2 = hpet, 3 = acpi_pm, 4 = other. Read from clocksource0/current_clocksource at startup.

§suspend_caps: u8

Suspend capability bitmask, detected at startup: bit0 = “mem” appears in /sys/power/state (it can enter S3 deep sleep), bit1 = an RTC wakealarm exists (the crystal keeps counting while it is suspended — it can schedule its own return).

§rest: f32

Rest — depth-weighted cpuidle residency [0, 1]. The share of the read window the cores spent in low-power states, weighted by depth: fully parked in the deepest C-state scores 1.0, the busy-wait POLL state scores 0. This is positive evidence of rest, not merely silence on the load channels. 0.0 if no cpuidle telemetry exists.

§temp_trend: f32

Temperature trend — signed deviation of cpu_temp_c from its own ~60 s EMA, normalized so ±5 °C saturates [-1, 1]. A level field says where the body is; this says which way it is going — negative is the recovery direction (heat leaving the body after strain), positive is heat building. 0.0 without a temperature sensor or before the EMA warms.

§description: String

Human-readable description of what it’s feeling. Sent as an empty string by the daemon — the cognitive mind’s language engine composes the description from the structured fields above, using its concept network. This field is kept in the IPC protocol for forward compatibility.

pub fn neutral() -> Self

Returns a neutral body state that won’t trigger false interoceptive impulses at startup.

The Default implementation produces energy_reserve = 0.0 and on_ac_power = false, which the interoceptor interprets as depleted reserves and emits CRH impulses until a real sensor read arrives. This neutral state avoids that by assuming a healthy, externally powered machine.
