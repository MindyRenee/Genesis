Core-state snapshot — the mind’s wire contract for GET_STATE_SNAPSHOT.

§Why this type exists

GET_STATE returns the raw GenesisCoreState — the brain’s authoritative memory image, schema-versioned by header.version. That is the right payload for body inspection (the Rust test harness and forensics read it that way), but it is the wrong payload for the cognitive mind: every consumer then has to mirror the brain’s byte layout in its own language, and the mirror has no tripwire. A schema bump does not fail — it returns plausible numbers read from the wrong fields. That has happened twice (v3→v4 and v4→v5 offset bugs) and nearly a third time (the transient v6 layout).

This struct is the anti-corruption layer between the two: a fixed-layout DTO that carries exactly what the mind consumes, mapped field-by-field in From<&GenesisCoreState>. The brain’s schema can evolve — fields move, blocks insert, versions bump — and the wire contract only changes when this file intentionally changes, under its own SNAPSHOT_VERSION. A renamed or retyped source field fails to compile here; it cannot silently re-encode on the wire.

The payload is self-describing: magic, version, and state_size lead the struct so a mismatched or foreign buffer is rejected before a single field offset is trusted.

Deliberately absent: the coupling matrix, per-chemical dynamics (level/baseline/velocity/tonic/phasic/vesicular), the manifest, ions, zones’ task bookkeeping, and every other field the mind does not read. The snapshot is a projection, not a copy — fields are added here when a consumer needs them, never because the brain gained them.

Constants§

SNAPSHOT_MAGIC
Magic bytes identifying a CoreStateSnapshot payload. ASCII "GSS1" — distinct from the state file’s "GNSX" so a raw GenesisCoreState can never be mistaken for a snapshot.
SNAPSHOT_VERSION
Snapshot schema version. Bump when this layout changes in any way that breaks binary compatibility — independently of the brain’s SCHEMA_VERSION, which this type exists to decouple from.
