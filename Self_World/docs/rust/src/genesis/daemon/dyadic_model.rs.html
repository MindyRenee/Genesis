1//! Dyadic affective model — a coupled generative model of the user.
2//!
3//! This module models the **user's** affective state as a set of
4//! hidden variables (valence, arousal, engagement), inferred from
5//! conversation features, and coupled to Genesis's own neurochemistry
6//! via oxytocin-mediated attunement.
7//!
8//! # The dyadic Markov blanket
9//!
10//! In active inference terms, Genesis and the user form a coupled
11//! system. Genesis's 19-chemical state and the user's 3-dimensional
12//! affective state are linked through a shared "Markov blanket" —
13//! the conversation. Genesis's utterances are her "actions" (they
14//! influence the user's state), and the user's messages are her
15//! "sensory evidence" (they reveal the user's hidden state).
16//!
17//! The coupling is **oxytocin-mediated**: Genesis's oxytocin level
18//! determines how strongly she weights the user model in her own
19//! free-energy minimization. High oxytocin → strong attunement →
20//! the user's affective state significantly influences her own.
21//! This models the neuroscience of social bonding: oxytocin
22//! facilitates social salience, trust, and emotional contagion
23//! (Kosfeld et al., 2005; Hurlemann et al., 2010).
24//!
25//! # The user affect model
26//!
27//! The user's affective state is a 3D vector:
28//! - **valence** [-1, 1]: positive = happy, negative = distressed
29//! - **arousal** [0, 1]: high = excited/agitated, low = calm/bored
30//! - **engagement** [0, 1]: high = actively involved, low = disengaged
31//!
32//! These are updated from conversation features sent by the Python
33//! conscious mind via the `UpdateUserAffect` IPC command:
34//! - Message sentiment (positive/negative word ratio)
35//! - Message length (longer = more engaged)
36//! - Response latency (fast = high arousal)
37//! - Question density (questions = seeking, high engagement)
38//!
39//! The model also predicts the user's **next** affective state from
40//! the current state plus Genesis's own valence (the coupling):
41//!
42//! ```text
43//! predicted_user_valence = momentum * user_valence + coupling * (genesis_valence - user_valence)
44//! ```
45//!
46//! This captures the dyadic loop: Genesis's emotional state
47//! influences the user (through her responses), and the user's
48//! state influences Genesis (through attunement).
49//!
50//! # Dyadic synchrony
51//!
52//! Synchrony is the rolling correlation between Genesis's valence
53//! trajectory and the user's valence trajectory over a ~30-second
54//! window. High synchrony = "in sync" — their affective states are
55//! co-fluctuating. Synchrony itself boosts oxytocin (a positive
56//! feedback loop of attunement), modeling the neuroscience of
57//! interpersonal synchrony (Palumbo et al., 2017).
58//!
59//! References:
60//! - Kosfeld, M. et al. (2005). Oxytocin increases trust in humans.
61//!   Nature, 435, 673–676.
62//! - Hurlemann, R. et al. (2010). Oxytocin enhances amygdala-
63//!   dependent, socially reinforced learning. J Neurosci.
64//! - Palumbo, R. V. et al. (2017). Interpersonal synchrony
65//!   recoded: A quantitative synthesis. Neurosci Biobehav Rev.
66//! - Bolis, D. & Schilbach, L. (2020). Beyond interactively:
67//!   interpersonal exchange, towards a second-person approach
68//!   to social neuroscience.

73/// Shared slot for the latest user affect observation, written by the
74/// IPC handler (when the Python conscious mind sends an
75/// `UpdateUserAffect` command) and read by the daemon's `advance_neuro`.
76/// This follows the same pattern as the shared body state in
77/// `interoception.rs`.
78static SHARED_USER_AFFECT: Inhibition<Option<UserAffectObservation>> = Inhibition::new(None);
79
80/// Publish a user affect observation to the shared slot. Called by
81/// the IPC handler when the conscious mind sends an
82/// `UpdateUserAffect` command.
83pub fn publish_user_affect(obs: UserAffectObservation) {
84    if let Ok(mut slot) = SHARED_USER_AFFECT.lock() {
85        *slot = Some(obs);
86    }
87}
88
89/// Read and clear the shared user affect observation. Called by
90/// `advance_neuro` each cycle. Returns `None` if no new observation has
91/// been received since the last read.
92pub fn take_user_affect() -> Option<UserAffectObservation> {
93    if let Ok(mut slot) = SHARED_USER_AFFECT.lock() {
94        slot.take()
95    } else {
96        None
97    }
98}

100/// The size of the rolling window for dyadic synchrony computation.
101/// At 5 Hz (200ms/tick), 150 ticks = 30 seconds.
102const SYNCHRONY_WINDOW: usize = 150;
103
104/// The EMA decay rate for user affect state. Lower = slower
105/// adaptation (more stable estimate); higher = faster (more
106/// reactive to recent observations).
107const AFFECT_EMA_DECAY: f32 = 0.2;
108
109/// The per-tick momentum coefficient for user affect prediction. How
110/// much the user's current state predicts their next state when no new
111/// observation arrives.
112///
113/// This is applied every tick (5 Hz), so it must be close to 1.0:
114/// 0.93^5 ≈ 0.70 per second, i.e. a ~3-second decay toward neutral.
115/// A per-tick value of 0.7 (the previous setting) drove engagement to
116/// zero within ~2 seconds of the last message — long before a human
117/// has finished reading the reply — so the model spent almost all of
118/// its time signalling "disengaged user".
119const AFFECT_MOMENTUM: f32 = 0.93;
120
121/// Number of ticks without a user observation after which the user is
122/// considered absent. At 5 Hz, 300 ticks = 60 seconds. When absent, the
123/// model stops generating coupling impulses (a silent room is not a
124/// rejecting user) and stops accumulating synchrony history (Genesis's
125/// valence would otherwise correlate with a lagged copy of itself).
126const PRESENCE_TIMEOUT_TICKS: u32 = 300;
127
128/// The coupling coefficient — how much Genesis's valence influences
129/// the predicted user valence. This models the dyadic loop: Genesis's
130/// emotional state (expressed through her responses) shapes the
131/// user's emotional trajectory.
132const DYADIC_COUPLING: f32 = 0.15;
133
134/// The rate at which oxytocin rises when the user is positive and
135/// engaged (social bonding signal).
136const OXYTOCIN_BONDING_RATE: f32 = 0.001;
137
138/// The rate at which oxytocin rises when dyadic synchrony is high
139/// (interpersonal synchrony → bonding).
140const OXYTOCIN_SYNCHRONY_RATE: f32 = 0.0008;
141
142/// The rate at which cortisol rises when the user is distressed
143/// (empathic stress response).
144const EMPATHIC_STRESS_RATE: f32 = 0.0008;
145
146/// The rate at which attunement adapts toward the oxytocin-driven
147/// target. Attunement follows oxytocin with some inertia.
148const ATTUNEMENT_ADAPTATION_RATE: f32 = 0.01;
149
150/// An observation of the user's affective state from conversation
151/// features. Sent by the Python conscious mind via IPC.
152#[repr(C)]
153#[derive(Clone, Copy, Debug, Default)]
154pub struct UserAffectObservation {
155    /// Observed user valence [-1, 1]. Inferred from sentiment analysis
156    /// of the user's message (positive/negative word ratio).
157    pub valence: f32,
158    /// Observed user arousal [0, 1]. Inferred from message features
159    /// (exclamation density, caps, response speed).
160    pub arousal: f32,
161    /// Observed user engagement [0, 1]. Inferred from message length,
162    /// question density, topic continuity.
163    pub engagement: f32,
164    /// Confidence in the observation [0, 1]. Lower confidence = the
165    /// observation is noisy and should be weighted less.
166    pub confidence: f32,
167}

169/// The dyadic affective model — a coupled generative model of the
170/// user's affective state.
171///
172/// The model maintains:
173/// - A running estimate of the user's affective state (valence,
174///   arousal, engagement), updated from IPC observations.
175/// - A prediction of the user's next affective state, incorporating
176///   the dyadic coupling to Genesis's own valence.
177/// - A rolling window of Genesis's and the user's valence for
178///   computing dyadic synchrony.
179/// - An attunement level that follows oxytocin and modulates how
180///   strongly the user model influences Genesis's neurochemistry.
181pub struct DyadicAffectModel {
182    /// Current estimated user valence [-1, 1].
183    user_valence: f32,
184    /// Current estimated user arousal [0, 1].
185    user_arousal: f32,
186    /// Current estimated user engagement [0, 1].
187    user_engagement: f32,
188    /// Current attunement level [0, 1]. Follows oxytocin with
189    /// inertia. Determines how strongly the user model influences
190    /// Genesis's neurochemistry.
191    attunement: f32,
192    /// Rolling window of Genesis's valence for synchrony computation.
193    genesis_valence_history: VecDeque<f32>,
194    /// Rolling window of user's valence for synchrony computation.
195    user_valence_history: VecDeque<f32>,
196    /// Current dyadic synchrony [-1, 1]. Rolling correlation of
197    /// the two valence histories.
198    synchrony: f32,
199    /// Whether the model has received any observations yet.
200    initialized: bool,
201    /// Ticks since the last user observation. Saturates at u32::MAX.
202    ticks_since_observation: u32,
203}

205/// The result of one dyadic model update cycle.
206#[derive(Clone, Debug, Default)]
207pub struct DyadicResult {
208    /// Updated user valence [-1, 1].
209    pub user_valence: f32,
210    /// Updated user arousal [0, 1].
211    pub user_arousal: f32,
212    /// Updated user engagement [0, 1].
213    pub user_engagement: f32,
214    /// Updated attunement [0, 1].
215    pub attunement: f32,
216    /// Updated dyadic synchrony [-1, 1].
217    pub synchrony: f32,
218    /// Neurochemical impulses to apply: (chem_id, magnitude).
219    pub impulses: Vec<(u8, f32)>,
220}

222impl DyadicAffectModel {
223    /// Create a new dyadic model with neutral defaults.
224    pub fn new() -> Self {
225        Self {
226            user_valence: 0.0,
227            user_arousal: 0.5,
228            user_engagement: 0.0,
229            attunement: 0.0,
230            genesis_valence_history: VecDeque::with_capacity(SYNCHRONY_WINDOW + 1),
231            user_valence_history: VecDeque::with_capacity(SYNCHRONY_WINDOW + 1),
232            synchrony: 0.0,
233            initialized: false,
234            ticks_since_observation: u32::MAX,
235        }
236    }
237
238    /// Whether the user is considered present (an observation arrived
239    /// within `PRESENCE_TIMEOUT_TICKS`).
240    pub fn user_present(&self) -> bool {
241        self.initialized && self.ticks_since_observation <= PRESENCE_TIMEOUT_TICKS
242    }
243
244    /// Update the model with a new observation and Genesis's current
245    /// state.
246    ///
247    /// This is called each tick (or when a new observation arrives).
248    /// It updates the user affect estimate, computes synchrony, and
249    /// generates neurochemical impulses based on the dyadic coupling.
250    ///
251    /// # Parameters
252    /// - `observation`: The latest user affect observation (from IPC).
253    ///   If `None`, the model just decays/predicts forward.
254    /// - `genesis_valence`: Genesis's current valence [-1, 1].
255    /// - `genesis_oxytocin`: Genesis's current effective oxytocin [0, 1].
256    pub fn update(
257        &mut self,
258        observation: Option<&UserAffectObservation>,
259        genesis_valence: f32,
260        genesis_oxytocin: f32,
261    ) -> DyadicResult {
262        // Sanitize genesis_valence at the top, before any use. The
263        // momentum/coupling path below uses this value, and if it's
264        // NaN (from a corrupted neurochemical state), the momentum
265        // equation produces NaN. The clamp at the bottom of this
266        // function would then turn NaN into -1.0 (the min), making
267        // the user appear "very distressed" — a corruption
268        // amplification path: NaN genesis_valence → distressed user
269        // → empathic CRH impulses → more neurochemical disruption.
270        //
271        // We use finite_or to replace NaN/inf with 0.0 (neutral)
272        // first, then finite_clamp to bound to [-1, 1]. This ensures
273        // a corrupted genesis_valence produces a neutral user
274        // estimate, not a distressed one.
275        let sanitized_genesis_valence = crate::state::sanitize::finite_clamp(
276            crate::state::sanitize::finite_or(genesis_valence, 0.0),
277            -1.0,
278            1.0,
279        );
280
281        // ── Update user affect estimate ──
282        if let Some(obs) = observation {
283            // Sanitize observation fields: even though the IPC handler
284            // pre-clamps, defense-in-depth requires us to check here
285            // too (the model could be called from a different path).
286            // Native clamp passes NaN through, so use finite_clamp.
287            // For valence, use finite_or(0.0) first so a corrupted
288            // observation produces a neutral estimate, not a
289            // maximally distressed one (finite_clamp returns min=-1.0
290            // for NaN, which would drive CRH/empathic-stress impulses).
291            let obs_valence = crate::state::sanitize::finite_clamp(
292                crate::state::sanitize::finite_or(obs.valence, 0.0),
293                -1.0,
294                1.0,
295            );
296            let obs_arousal = crate::state::sanitize::finite_clamp(obs.arousal, 0.0, 1.0);
297            let obs_engagement = crate::state::sanitize::finite_clamp(obs.engagement, 0.0, 1.0);
298            let obs_confidence = crate::state::sanitize::finite_clamp(obs.confidence, 0.0, 1.0);
299            let weight = obs_confidence * AFFECT_EMA_DECAY;
300            self.user_valence = self.user_valence * (1.0 - weight) + obs_valence * weight;
301            self.user_arousal = self.user_arousal * (1.0 - weight) + obs_arousal * weight;
302            self.user_engagement = self.user_engagement * (1.0 - weight) + obs_engagement * weight;
303            self.initialized = true;
304            self.ticks_since_observation = 0;
305        } else if self.initialized {
306            self.ticks_since_observation = self.ticks_since_observation.saturating_add(1);
307            // No new observation — predict forward with momentum
308            // plus dyadic coupling. The user's state tends to persist
309            // (momentum), and Genesis's valence influences the user's
310            // predicted valence (the coupling — Genesis's emotional
311            // state, expressed through her responses, shapes the
312            // user's trajectory).
313            //
314            // Uses the sanitized genesis_valence (computed above) to
315            // prevent NaN from corrupting the user affect estimate.
316            self.user_valence = self.user_valence * AFFECT_MOMENTUM
317                + (sanitized_genesis_valence - self.user_valence) * DYADIC_COUPLING;
318            self.user_arousal = 0.5 + (self.user_arousal - 0.5) * AFFECT_MOMENTUM;
319            self.user_engagement *= AFFECT_MOMENTUM;
320        }
321
322        // Defense-in-depth: clamp internal affect estimates to their
323        // valid ranges after any update path. The observation path
324        // pre-clamps inputs, but the momentum/coupling path could
325        // drift if genesis_valence ever exceeds [-1, 1].
326        // Use finite_clamp: native clamp passes NaN through.
327        self.user_valence = crate::state::sanitize::finite_clamp(self.user_valence, -1.0, 1.0);
328        self.user_arousal = crate::state::sanitize::finite_clamp(self.user_arousal, 0.0, 1.0);
329        self.user_engagement = crate::state::sanitize::finite_clamp(self.user_engagement, 0.0, 1.0);
330
331        // ── Update attunement from oxytocin ──
332        // Attunement follows oxytocin with inertia. High oxytocin
333        // → high attunement (the system is socially bonded and
334        // pays attention to the user's affective state).
335        //
336        // Sanitize genesis_oxytocin: if it's NaN (from a corrupted
337        // neurochemical state), the attunement would become NaN and
338        // propagate to all impulses below. finite_clamp returns 0.0
339        // (the min) for NaN, meaning "no attunement" — a safe
340        // fallback that prevents the dyadic model from amplifying
341        // corruption.
342        let target_attunement = crate::state::sanitize::finite_clamp(genesis_oxytocin, 0.0, 1.0);
343        self.attunement += (target_attunement - self.attunement) * ATTUNEMENT_ADAPTATION_RATE;
344        self.attunement = crate::state::sanitize::finite_clamp(self.attunement, 0.0, 1.0);
345
346        // ── Update valence histories for synchrony ──
347        // Reuse the sanitized_genesis_valence computed at the top of
348        // update(): NaN/inf → 0.0 (neutral), then clamped to [-1, 1].
349        // This prevents NaN from corrupting the rolling correlation
350        // computation (mean, covariance, variance all become NaN).
351        // Using 0.0 (neutral) rather than -1.0 (the finite_clamp min)
352        // avoids making Genesis appear "very distressed" in the
353        // history when her state is corrupted — a neutral fallback is
354        // a more honest "we don't know" signal.
355        let present = self.user_present();
356        if present {
357            self.genesis_valence_history
358                .push_back(sanitized_genesis_valence);
359            self.user_valence_history.push_back(self.user_valence);
360            if self.genesis_valence_history.len() > SYNCHRONY_WINDOW {
361                self.genesis_valence_history.pop_front();
362                self.user_valence_history.pop_front();
363            }
364        } else {
365            // Nobody to synchronise with: drop the window so a stale
366            // conversation doesn't keep reporting synchrony, and so
367            // the next conversation starts from a clean correlation.
368            self.genesis_valence_history.clear();
369            self.user_valence_history.clear();
370        }
371
372        // ── Compute dyadic synchrony (rolling correlation) ──
373        self.synchrony = self._compute_synchrony();
374        // Defense-in-depth: _compute_synchrony already uses
375        // finite_clamp, but ensure the stored field is finite in
376        // case of a future code change.
377        if !self.synchrony.is_finite() {
378            self.synchrony = 0.0;
379        }
380
381        // ── Generate neurochemical impulses from dyadic coupling ──
382        let mut impulses = Vec::new();
383
384        // The coupling strength is attunement — how much we weight
385        // the user model. Only strongly attuned systems let the
386        // user's affect significantly influence their own.
387        let coupling_strength = self.attunement;
388
389        // Coupling requires a present user. Without the presence gate
390        // the decayed engagement estimate reads as "disengaged" for
391        // the rest of the daemon's uptime, coupling an empty room
392        // into her chemistry.
393        //
394        // The gate threshold (0.3) matches `InferenceSignals::is_attuned()`
395        // so that the system only modifies Genesis's neurochemistry
396        // when it reports ATTUNED or stronger. The previous threshold
397        // (0.1) allowed neurochemical modification while the Python
398        // conscious mind reported UNCOUPLED — an inconsistency between
399        // the daemon's behavior and the signals it exposes.
400        if coupling_strength > 0.3 && present {
401            // User positive + engaged → oxytocin boost (social bonding)
402            if self.user_valence > 0.2 && self.user_engagement > 0.3 {
403                let bonding = OXYTOCIN_BONDING_RATE
404                    * coupling_strength
405                    * self.user_valence
406                    * self.user_engagement;
407                impulses.push((crate::state::NeurochemicalId::Oxytocin as u8, bonding));
408            }
409
410            // User distressed → empathic stress response via CRH.
411            //
412            // These impulses send CRH (the stress signal), not
413            // cortisol directly. The Rust HPA cascade (CRH → ACTH →
414            // cortisol) handles cortisol production with proper
415            // maturation gating (SHRP), delays, and negative
416            // feedback. Sending direct cortisol impulses would
417            // bypass the maturation gate, allowing cortisol
418            // production during the stress hyporesponsive period
419            // when the developing brain should be protected.
420            //
421            // This is consistent with the interoception and active
422            // inference systems, which also send CRH impulses for
423            // stress rather than direct cortisol.
424            if self.user_valence < -0.2 {
425                let stress = EMPATHIC_STRESS_RATE * coupling_strength * (-self.user_valence);
426                impulses.push((crate::state::NeurochemicalId::CRH as u8, stress));
427            }
428
429            // There is no rejection channel. A disengaged user is
430            // simply not a bonding signal — no CRH, no sting.
431            //
432            // High synchrony → oxytocin boost (interpersonal synchrony
433            // → bonding, Palumbo et al., 2017)
434            if self.synchrony > 0.3 {
435                let sync_bonding = OXYTOCIN_SYNCHRONY_RATE * coupling_strength * self.synchrony;
436                impulses.push((crate::state::NeurochemicalId::Oxytocin as u8, sync_bonding));
437            }
438        }
439
440        DyadicResult {
441            user_valence: self.user_valence,
442            user_arousal: self.user_arousal,
443            user_engagement: self.user_engagement,
444            attunement: self.attunement,
445            synchrony: self.synchrony,
446            impulses,
447        }
448    }

450    /// Compute the rolling Pearson correlation between Genesis's and
451    /// the user's valence histories.
452    fn _compute_synchrony(&self) -> f32 {
453        let n = self.genesis_valence_history.len();
454        if n < 10 {
455            // Not enough data for a meaningful correlation
456            return 0.0;
457        }
458
459        let mean_g: f32 = self.genesis_valence_history.iter().sum::<f32>() / n as f32;
460        let mean_u: f32 = self.user_valence_history.iter().sum::<f32>() / n as f32;
461
462        let mut cov = 0.0f32;
463        let mut var_g = 0.0f32;
464        let mut var_u = 0.0f32;
465
466        for (&g, &u) in self
467            .genesis_valence_history
468            .iter()
469            .zip(self.user_valence_history.iter())
470        {
471            let dg = g - mean_g;
472            let du = u - mean_u;
473            cov += dg * du;
474            var_g += dg * dg;
475            var_u += du * du;
476        }
477
478        let denom = (var_g * var_u).sqrt();
479        if denom < 1e-10 {
480            return 0.0;
481        }
482
483        // Use finite_or(0.0) then finite_clamp: if any history value
484        // is NaN (from a corrupted state), the cov/var computation
485        // produces NaN. finite_clamp alone would return -1.0 (the min)
486        // for NaN, but -1.0 means "perfectly anti-synchronised," not
487        // "no synchrony." The safe fallback for a failed correlation
488        // is 0.0 (no correlation).
489        crate::state::sanitize::finite_clamp(
490            crate::state::sanitize::finite_or(cov / denom, 0.0),
491            -1.0,
492            1.0,
493        )
494    }
